# Venyl iOS — кандидат для первой сборки

Это исходники iOS-контейнера и задание macOS-сборки. IPA ещё НЕ собран.
Полноценное нативное музыкальное приложение ещё НЕ завершено.

Контейнер открывает актуальный Venyl по HTTPS внутри WKWebView с постоянным
хранилищем cookies. Песни и аккаунты остаются на существующем сервере.
В архиве нет песен, базы, паролей или ключей доступа.

## Что подготовлено
SwiftUI-приложение, WKWebView, загрузочный индикатор, экран сетевой ошибки,
повторное открытие, системное подтверждение действий (в том числе удаления),
проект XcodeGen, иконка из существующих ресурсов Venyl, GitHub Actions.

## Получить настоящий двоичный IPA
1. После разрешения владельца добавить содержимое в отдельную ветку
   `venyl-ios-build` репозитория kaljanchik339-glitch/Venyl_Music.
2. Push запускает `.github/workflows/venyl-ios.yml` на macOS.
3. Проверить успешную компиляцию Xcode, скачать артефакт Venyl-unsigned-IPA.
4. Внутри будет Venyl-unsigned.ipa с ARM64 приложением, а не ZIP исходников.
5. Для установки нужна отдельная подпись под устройство. Этот workflow
   не выдаёт и не подменяет сертификат Apple и provisioning profile.

## Что НЕ проверено / не готово
- Swift не компилировался здесь: доступная среда Linux, Xcode отсутствует.
- Авторизация ChatGPT внутри WKWebView может быть ограничена провайдером.
  Cookies Safari не переносятся автоматически. При блокировке нужен
  поддерживаемый системный вход и обмен сессией, а не обход входа.
- Фоновая музыка, экран блокировки, AirPods и прерывания внутри WKWebView
  не гарантированы. Нужна интеграция AVPlayer и поддерживаемый доступ
  к аудио с авторизацией; не включено фиктивное обещание background audio.
- Загрузка через Files, safe area, авторизация и повторный запуск требуют
  тестов на реальном устройстве после подписания.
- Интерфейс загружается с сервера; офлайн-режима и скачивания песен нет.

Рабочий сайт и ветка main этим архивом не изменены.
